# 代码变更文档（doc）

本目录用于维护 **Textop / TextOpTracker** 代码库的每次功能更新记录：改了什么功能、动了哪些文件、依据是什么、怎么回退。

## 目录约定

| 文件 | 用途 |
|---|---|
| `README.md` | 本说明：目录用途与维护约定 |
| `CHANGELOG.md` | 变更记录主文件，**最新变更在最上方**，每次改动追加一条 |

## 每次改动需要记录的内容

在 `CHANGELOG.md` 顶部新增一条，包含：

1. **日期 + 主题**（一句话说明本次改动的目的）；
2. **新增 / 修改的功能**：用表格列出「功能 → 实现方式 → 涉及文件」；
3. **关键参数及依据**：参数取值来自哪篇论文 / 哪个参考仓库 / 哪次实测，写清楚出处；
4. **本次未做的部分**及原因（避免后人误以为漏改）；
5. **回退方式**：如何恢复到改动前的行为（改回哪个类 / 删掉哪个 EventTerm / 使用哪份备份）。

## 维护约定

- 只记录**代码层面**的变化；纯超参调优建议放在条目末尾的「备注」中。
- 改动一旦合并，就**不要修改历史条目**，需要修正时新增一条并在其中注明「修正 xx 日条目」。
- 涉及论文/参考仓库的结论，尽量给出具体文件或章节，便于复核。
- 提交前建议对改动文件做语法自检：
  ```bash
  python -m py_compile <改动的 .py 文件>
  ```
